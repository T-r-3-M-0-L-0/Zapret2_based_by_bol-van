# Профили и Lua в zapret2 — простыми словами

Этот гайд для тех, кто не хочет разбираться в сетевых деталях. Здесь — только то, что нужно, чтобы самому собрать рабочий обход блокировки. Если захочется глубже — есть `STRATEGY_GUIDE.md` (для инженеров) и `LUA_GUIDE.md` (по Lua).

---

## Что вообще происходит (за 30 секунд)

Провайдер стоит между вами и интернетом и **подсматривает**, куда вы стучитесь. Увидел запрещённый сайт (например, YouTube) — обрывает соединение.

**zapret2** делает хитрость: ваш запрос к сайту режется на кусочки или подмешивается «мусорный» пакет так, что провайдер **не узнаёт** адрес сайта, а настоящий сервер — узнаёт и отвечает нормально.

Для этого zapret2 нужен **набор правил**: какой трафик трогать и что с ним делать. Эти правила и называются **профилями**.

---

## Профиль — это правило из трёх частей

Представьте инструкцию для охранника:

```
КОГО проверять:   посетителей с пропуском "youtube.com"     ← фильтр
КОГДА проверять:  только при первом входе                   ← условие
ЧТО делать:       поменять пропуск на "ozon.ru" на 1 секунду ← действие
```

В файле профиля это выглядит так (файл `profiles\70_google.conf`):

```
--filter-tcp=443 --filter-l7=tls --hostlist="%LISTS%list-google.txt"   ← КОГО
--payload=tls_client_hello --out-range=-d10                            ← КОГДА
--lua-desync=fake:blob=tls_google:tcp_ts=-600000:repeats=6             ← ЧТО, шаг 1
--lua-desync=fakedsplit:pattern=0x00:tcp_ts=-600000:ip_id=zero         ← ЧТО, шаг 2
```

Разбирать каждое слово не обязательно. Важно понимать структуру:

| Часть | За что отвечает | Что менять руками |
|---|---|---|
| `--filter-tcp=443` | порт (443 = обычный HTTPS) | почти никогда |
| `--hostlist-domains=...` или `--hostlist="..."` | **список сайтов**, к которым применяется правило | **чаще всего меняете именно это** |
| `--payload=tls_client_hello` | срабатывать на первом «приветствии» соединения | не трогайте |
| `--lua-desync=...` | **приём обхода** | копируйте готовые из других профилей |

## Как устроена папка `profiles\`

Каждый файл — одно правило. Имя файла решает **порядок**: правила применяются по алфавиту имён, и срабатывает **первое подошедшее**.

```
00_base.conf                  ← общие настройки, нужен всегда, не трогайте
10_quic_general.conf          ← YouTube-видео (ускоритель QUIC)
20_discord_voice_udp.conf     ← голосовые каналы Discord
30_discord_updates.conf       ← загрузчик Discord (лечит "Checking update")
40_discord_media_images.conf  ← картинки и аватарки в Discord
50_discord_cdn.conf           ← файлы/вложения Discord
60_discord_main.conf          ← сам Discord (сайт и приложение)
70_google.conf                ← YouTube
71_github.conf                ← GitHub
80_general_tcp.conf           ← общий список сайтов (list-general.txt)
81_ipset_quic.conf            ← запасные правила по IP
82_ipset_tcp.conf
90_game_udp.conf              ← игры
91_udp_catchall.conf          ← всё остальное
```

Порядок важен: сначала узкие правила («только updates.discord.com»), потом широкие («весь список сайтов»). Если поставить широкое первым, узкие никогда не сработают.

## Три практических сценария

### Сценарий 1. «Сайт X не открывается»

1. Откройте `profiles\71_github.conf` — он самый простой. Скопируйте его под новым именем, например `72_mysite.conf`.
2. Вместо `--hostlist="%LISTS%list-github.txt"` напишите `--hostlist-domains=mysite.com,www.mysite.com`.
3. В первой строке (после `#`) напишите, что это за профиль — она показывается в меню.
4. Запустите `service2.bat` → пункт **7** (собрать Custom.bat) → Enter (все профили).
5. Пункт **5** (запуск без службы) → выбрать `Custom.bat` → проверить сайт в браузере.
6. Работает? Пункт **1** → `Custom.bat` → правило теперь в автозапуске.

### Сценарий 2. «Сайт X не открывается, и простое правило не помогло»

Значит, блокировка жёстче. Берите «тяжёлое» действие из профиля Discord (`30_discord_updates.conf`) — скопируйте обе строки `--lua-desync` оттуда в свой профиль вместо лёгких. Эти две строки — самое мощное, что у нас есть; они проверены на Ростелекоме/ЕСК/МГТС.

### Сценарий 3. «Хочу убрать правило» (например, игры лагать начали)

Не удаляйте файлы — при сборке (пункт 7) просто **введите номера нужных профилей через запятую** вместо Enter. Соберётся `Custom.bat` без лишних.

## А что такое Lua и надо ли в него лезть?

**Lua — это маленькие программки, которые выполняют приёмы обхода.** Каждое `--lua-desync=что-то` вызывает программку с именем «что-то»: `fake` (подбросить мусорный пакет), `multisplit` (разрезать пакет на части), `multidisorder` (разрезать и перепутать порядок) и т.д.

Хорошая новость: **писать на Lua самому почти никогда не нужно.** Все приёмы уже написаны — вы только комбинируете их в профилях, как кубики. Своя Lua-программа понадобится, только если вы захотите приём, которого нет в списке — тогда открывайте `LUA_GUIDE.md`, там шаблон.

Единственное место, где Lua встречается в обычной жизни — строки `--lua-init=` в `00_base.conf`. Они готовят «заготовки пакетов» (например, поддельное приветствие от имени ozon.ru). Это как разогреть духовку перед готовкой: один раз при старте, дальше профили пользуются заготовками по имени (`blob=tls_ozon`).

## Памятка на стену

- Всё делается через **`service2.bat`** (двойной клик, согласиться на права администратора).
- Новый сайт → копия простого профиля → поменять домен → собрать (п.7) → проверить (п.5) → в автозапуск (п.1).
- Сломалось — пункт **2** (удалить службу), потом пункт **1** и выбрать `Custom.bat` заново.
- Не запускайте одновременно zapret1 (winws.exe) и zapret2 (winws2.exe) — они мешают друг другу. service2 сам гасит старый при запуске нового.
- Проверить, что всё живо: пункт **3** — должно быть три зелёных кода (200/403/404 — всё хорошо, 000 — плохо).

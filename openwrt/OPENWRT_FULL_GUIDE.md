# OpenWrt: от первых шагов до инженерной работы

Полный путь по OpenWrt на живом примере нашего сетапа: Tenda BE12 Pro +
Zapret-Manager (LuCI + SPA :7788) + zapret2 + sTGWS + плагины.

---

## Часть 1. Первые шаги (для всех)

### 1.1 Что это такое
OpenWrt — Linux для роутера: вместо закрытой прошивки получаешь полноценную
систему с пакетным менеджером (apk/opkg), firewall (nftables), веб-панелью
LuCI и SSH.

### 1.2 Доступ
- **Веб-панель LuCI**: `http://192.168.1.1` (у тебя может быть другой адрес).
- **SSH**: `ssh root@192.168.1.1` — основной рабочий инструмент.
- **Копирование файлов**: `scp -O файл root@192.168.1.1:/tmp/`
  (флаг `-O` обязателен: в dropbear нет SFTP, без него scp падает с
  «sftp-server: not found»).

### 1.3 Пять команд, которыми покрывается 90% быта

```sh
logread -e zapret     # журнал (кольцевой буфер RAM)
service zapret2 restart
uci show zapret2      # конфиг в UCI (единая система настроек OpenWrt)
uci commit zapret2 && service zapret2 restart
reboot
```

### 1.4 Главные правила безопасности
1. **Не правь, не сняв копию**: `cp /etc/config/zapret2 /root/zapret2.bak`.
2. UCI-конфиги живут в `/etc/config/` — правка файла + `uci commit` +
   рестарт службы.
3. `/tmp` — это RAM: всё там умирает при ребуте. Постоянное — в `/etc`,
   `/opt`, `/root` (если хватает флеша).
4. Не знаешь, что делает команда — сначала `--help` или спроси.

### 1.5 Если что-то сломалось
- Нет интернета после правок → `logread | tail -50`, проверить
  `/etc/config/network` и `/etc/config/firewall`, откатить бэкап.
- LuCI не открывается → SSH живёт независимо; `service uhttpd restart`.
- Совсем всё плохо → failsafe-режим (зажать reset при загрузке) или
  повторная прошивка.

## Часть 2. Система OpenWrt подробно

### 2.1 Топ-15 команд, которые нужно знать

| # | Команда | Зачем |
|---|---|---|
| 1 | `logread` / `logread -f` / `logread -e <слово>` | Системный журнал (RAM-буфер): читать / в реальном времени / с фильтром |
| 2 | `service <имя> start\|stop\|restart\|enable\|disable` | Управление службами (enable/disable — автозапуск) |
| 3 | `uci show <конфиг>` | Показать конфиг: `uci show network`, `uci show zapret2` |
| 4 | `uci set X.Y.Z=V && uci commit X` | Изменить параметр и зафиксировать (без commit не применится) |
| 5 | `uci changes` / `uci revert X` | Что изменено, но не закоммичено / откатить незакоммиченное |
| 6 | `apk add <пакет>` / `apk del` / `apk list --installed` | Пакетный менеджер (в старых версиях — `opkg`) |
| 7 | `ps w` / `top` (или `htop`) | Процессы и нагрузка (по умолчанию busybox-версии) |
| 8 | `free -h` / `df -h` | Память / занятое место на флеше |
| 9 | `ip a` / `ip r` / `ip link` | Интерфейсы, адреса, таблица маршрутов |
| 10 | `ping` / `traceroute` / `nslookup <host> [server]` | Базовая диагностика связности и DNS |
| 11 | `curl -s -o /dev/null -w '%{http_code} %{time_total}' <url>` | Проверка HTTP-доступности с роутера |
| 12 | `nft list ruleset` / `nft list table inet fw4` | Текущие правила firewall (fw4 = nftables) |
| 13 | `wifi reload` / `wifi status` | Применить настройки Wi-Fi без ребута / состояние |
| 14 | `sysupgrade -b /tmp/backup.tar.gz` | Полный бэкап конфигов (восстановление: `sysupgrade -r`) |
| 15 | `crontab -l` / `/etc/init.d/cron restart` | Просмотр задач cron / применить правки cron |

Близко к топу, но ситуативно: `ubus call system board` (модель/версия),
`opkg` вместо `apk` на старых релизах, `swconfig`/`bridge` (свитч),
`tcpdump -i br-lan host <ip>` (снифер, ставится пакетом), `strings`/`grep`
для разбора бинарных конфигов.

### 2.2 Карта каталогов

| Путь | Что там | Особенности |
|---|---|---|
| `/etc/config/` | **Все главные конфиги** (UCI, текст) | network, firewall, dhcp, wireless, zapret2, rpcd… |
| `/etc/init.d/` | Скрипты служб | то, чем дёргает `service` |
| `/etc/rc.d/` | Симлинки автозапуска | создаются `service X enable` |
| `/etc/crontabs/root` | Задачи cron | после правки: `/etc/init.d/cron restart` |
| `/etc/dropbear/` | Ключи SSH-сервера | authorized_keys для входа по ключу — тут |
| `/etc/hosts`, `/etc/resolv.conf` | Локальные имена, DNS | resolv.conf генерируется — править через UCI |
| `/etc/sysctl.conf` | Параметры ядра | применить: `sysctl -p` |
| `/opt/` | Сторонний софт | у нас: `/opt/zapret2` (lists, lua), zapret-manager-luci |
| `/www/` | Веб-файлы LuCI и панелей | `/www/luci-static/resources/view/*` — страницы LuCI |
| `/usr/share/luci/menu.d/` | Пункты меню LuCI (JSON) | сюда кладутся меню приложений |
| `/usr/share/rpcd/acl.d/` | Права доступа rpcd (JSON) | какие файлы/ubus-объекты доступны веб-сессии |
| `/usr/sbin`, `/usr/bin` | Утилиты | сюда ставятся zm-pluginctl и пр. |
| `/tmp/` | **RAM-диск** | логи, временное; всё стирается ребутом |
| `/root/` | Домашний каталог root | бэкапы, архивы установки |
| `/overlay/` + `/rom/` | Записываемый слой + прошивка RO | /rom — эталон; стереть /overlay = сброс к заводу |
| `/var/` | Симлинк на /tmp | не хранить важное |

### 2.3 Основные конфиги в /etc/config

| Файл | Отвечает за | Примеры ключей |
|---|---|---|
| `network` | Интерфейсы, VLAN, маршруты, WAN/LAN | `config interface 'wan'` |
| `wireless` | Wi-Fi (радио + сети) | `config wifi-iface` (ssid, key, encryption) |
| `dhcp` | dnsmasq: DHCP-раздача, DNS-форвардинг, статические аренды | `config host` (привязка IP к MAC) |
| `firewall` | Зоны, форвардинг, NAT, правила | `config zone`, `config redirect` (проброс портов) |
| `system` | Имя, часовой пояс, NTP, LED | `option hostname` |
| `dropbear` | SSH-демон | порт, ключи, запрет пароля |
| `rpcd` | Доступ веб-сессий к системе | права логина LuCI |
| `uhttpd` | Веб-сервер LuCI | порты 80/443, сертификаты |
| `zapret2` | Наши профили/стратегии/листы | профили, фильтры, тактики |

Формат UCI — секции `config <тип> [имя]` + `option ключ значение` +
`list ключ значение`. Читается глазами, правится хоть редактором, хоть
`uci set`. После правки файла вручную: `uci commit <имя>` + рестарт
соответствующей службы (или `reload_config` для network/dhcp/firewall).

### 2.4 Жизненный цикл изменения (системный)

```sh
cp /etc/config/network /root/network.bak     # 1. бэкап
vi /etc/config/network                        # 2. правка (или uci set)
uci commit network                            # 3. фиксация
service network reload                        # 4. применение без ребута
logread -e netifd                             # 5. проверка журнала
```

### 2.5 Пакеты и обновления
- `apk add curl jq tcpdump htop` — минимальный инженерный набор.
- `apk list --upgradable` — что можно обновить (SNAPSHOT: осторожно,
  обновление ядра тянет пересборку модулей — лучше sysupgrade целиком).
- `sysupgrade <image.bin>` — прошивка с сохранением конфигов;
  `sysupgrade -n` — чистая. Перед прошивкой: `sysupgrade -b`.

### 2.6 Диагностика «с чего начать»
1. `logread | tail -30` — последние ошибки.
2. `ip r` + `ping 1.1.1.1` — есть ли маршрут и связность.
3. `nslookup ya.ru` — жив ли DNS.
4. `service <подозреваемая> restart` + `logread -f` — смотреть старт.
5. `df -h` и `free` — не кончились ли флеш/память (частая причина
   «внезапных странностей» на роутерах).

## Часть 3. Работа с zapret на OpenWrt

### 3.1 Архитектура нашего сетапа

```
клиенты LAN/Wi-Fi → роутер (zapret2 nfqws2 перехватывает transit-трафик)
                  → провайдер
```

Ключевое отличие от Windows-схемы: перехватывается **транзит** (трафик
клиентов), а не трафик самого роутера. Поэтому:
- тесты с роутера (curl на роутере) идут мимо zapret2 — для проверки
  используем strategy-check с тестовой копией движка;
- один раз настроил — работает для всех устройств дома без установки чего-либо.

### 3.2 Где что лежит

| Что | Где |
|---|---|
| UCI-конфиг zapret2 | `/etc/config/zapret2` |
| Списки доменов/IP | `/opt/zapret2/lists/` |
| Lua-скрипты | `/opt/zapret2/lua/` |
| Панель SPA | `http://192.168.1.1:7788` |
| LuCI-вкладки zapret | LuCI → Службы → Zapret2 |
| Zapret-Manager | LuCI → Службы → Zapret-Manager + SPA :7788 |

### 3.3 Базовый цикл работы со стратегией
1. Симптом (что именно не грузится: видео? картинки? конкретный сервис?).
2. `logread -e zapret2` — есть ли ошибки движка.
3. Проверка через **Сравнение стратегий** (LuCI/SPA): прогон по целям
   без остановки основного движка.
4. Правка профиля в `/etc/config/zapret2` (или через панель) → рестарт.
5. Регрессия: проверить, что не отвалилось другое (игры, банки).

### 3.4 Cron-автоматика
`zhealth` — healthcheck по cron: пингует заведомо живые адреса (ya.ru и пр.),
и только если они отвечают, а целевые сервисы нет — пересобирает стратегию.
Маркер «это не неуплата» обязателен, иначе автоподбор сработает вхолостую.
Управление — из карточки в панели (расписание, кулдаун, лимит автоприменений).

## Часть 4. Инженерный уровень

### 4.1 Диск и память
- `df -h` / `free` — следить за флешем: логи и бэкапы только ротируемые.
- **ZRAM** (пункт в панели): на BE12 Pro с 512 МБ RAM даёт сжатый своп —
  имеет смысл при тяжёлых списках ipset; на слабых моделях (128 МБ) —
  обязателен.
- Не хранить историю проверок на роутере (наше решение: без истории прогонов).

### 4.2 Сеть
- **Hw flow offloading** (init.d openwrt flowtable): аппаратное ускорение
  NAT — с zapret2 совместимо только для неперехватываемого трафика; при
  странных потерях скорости проверять первым.
- **DoH на роутере** (https-dns-proxy): если Cloudflare DoH перестал
  отвечать — переключение апстрима или временный откат на провайдерский DNS
  (наш кейс: DoH Cloudflare отвалился → симптомы «половина интернета лёг»).
- Маркировка: `nft list ruleset | grep nfqws` — убедиться, что перехват
  стоит на transit-цепочках.

### 4.3 Наблюдаемость
- `logread -f` — живой журнал.
- Наши метрики: strategy-check прогоны, журнал `/tmp/zm-probe-calls.log`
  (маркер вызовов), `tc -s qdisc`, `conntrack -L | wc -l`.
- Базовая линия скорости: замер до/после изменений (яндекс-интернетомер,
  если speedtest недоступен из РФ).

### 4.4 Плагины Zapret-Manager (наша система)
Новая страница панели = **manifest.json + backend.sh**, без JavaScript:
- манифест описывает виджеты (status/table/button/log/form);
- backend — shell-скрипт, отвечающий JSON;
- установка: `zm-pluginctl install /tmp/my-plugin` или UI
  «Плагины → Менеджер плагинов»;
- спецификация — `PLUGIN_DEV.md` в пакете zm-plugin-system.
Тот же рендерер обслуживает SPA :7788 и LuCI «Службы → ZM плагины».

### 4.5 Перенос сетапа на другой роутер
`fz-openwrt-bundle.tar.gz` — пять пакетов (zapret2-config, strategy-check,
stgws-smart, zapret2-presets, zm-plugin-system). Порядок: 1→2→3→4, пятый
независим. У каждого установщика preflight `--check`, бэкапы и откат.
Детали — README внутри бандла и пакетов.

### 4.6 Безопасность при публикации
Перед выкладкой конфигов/гайдов на GitHub: вычистить локальные пути,
IP-адреса, адрес роутера, пароли/секреты (секрет tgws-прокси!), заменить
root на нейтральный user.

### 4.7 Методика изменений
1. Бэкап → правка → проверка → журнал (наш MIGRATION_ZAPRET2.md — 44
   раздела истории: что, зачем, чем проверено).
2. Одна правка = одна проверка. Никогда не менять два подсистемы разом
   (кейс: sTGWS + DoH одновременно — долго искали, что из двух сломалось).
3. Каждая нетривиальная находка — в гайд/журнал, чтобы не отлаживать дважды.

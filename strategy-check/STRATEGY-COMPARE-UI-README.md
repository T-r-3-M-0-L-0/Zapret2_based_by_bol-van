# Сравнение стратегий zapret2 в LuCI

Вкладка **Службы → Zapret2 → Сравнение стратегий** для роутера OpenWrt с zapret2 (Zapret Manager).

Адрес страницы — http://<ROUTER_IP>/cgi-bin/luci/admin/services/zapret2 . Обновите страницу, чтобы получить новую вкладку.

На этом роутере установлен `luci-app-zapret2 1.0.7-r1`. Сравнение встроено в этот интерфейс. Структура проверки взята из StressOzz Zapret Manager, включая контрольный тест, последовательное сравнение стратегий, успешные/все домены, сортировку и цвет относительно контроля. Референс изучен на коммите `b1a2714842459c47c66a435dcbe0bfb05b85810c`.

https://github.com/StressOzz/Zapret-Manager/blob/b1a2714842459c47c66a435dcbe0bfb05b85810c/ZapretManager_LuCI.sh

## Использование

1. Выберите стратегии. Флажок «Все сохранённые стратегии» включает в прогон также выключенные профили.
2. Выберите доменные списки. По умолчанию отмечены списки YouTube/Google. Флажок «Все используемые списки» выбирает все найденные положительные hostlist.
3. Укажите протокол, GET либо HEAD, число повторов, тайм-аут и лимит доменов. Значение 0 проверяет полный список. По умолчанию установлена выборка до 5 доменов из списка, один повтор и 6 секунд на запрос.
4. Нажмите «Начать проверку». Задание работает в отдельной сессии, поэтому можно закрыть страницу и вернуться к ней позже.
5. Сводная таблица обновляется после обработки очередного домена. Нажатие на ячейку показывает попытки запросов, HTTP-статус, код curl, размер ответа и время.
6. Для завершения прогона используйте «Остановить и восстановить службу». В таблице сохранятся частичные результаты.
7. Кнопка «Применить» в строке стратегии включает её в активной конфигурации (`uci enabled=1`) с резервной копией и перезапуском службы.

## Автоподбор стратегий (cron)

Нижняя секция вкладки управляет автономным контуром восстановления, работающим без участия человека.

1. Раз в час проверяются страницы и превью YouTube. Одновременно выполняются до трёх запросов. Ожидаются HTML, изображение или разрешённый редирект в пределах своего сайта. Для проверки самого медиа можно поместить свежий HTTPS URL `*.googlevideo.com/videoplayback?...` с параметром `expire` в файл `/etc/zapret2-health-media.url` (права 600). Без ссылки вывод относится только к странице и превью.
2. Два сбоя подряд на одном подтверждённом интерфейсе запускают сравнение, если доступны два из трёх контрольных сайтов. Через NetShift, при неизвестном пути и ошибках DNS автоматической смены нет.
3. Автотест проверяет включённые и выключенные профили. Заведомо неподходящие UDP-профили и порты исключаются до компиляции, несовместимые обычные hostlist — до сетевого запроса. Активные победители отмечаются для диагностики порядка профилей. Для выключенного кандидата нужны две дополнительные успешные попытки и два неуспешных контроля на одном IP и маршруте.
4. Перед применением сохраняется конфигурация. Если активная конфигурация не проходит две повторные проверки или служба не запускается, выполняется откат. Также перепроверяются ранее работавшие цели, чтобы обнаружить побочные эффекты широкого профиля. Оборванная транзакция обнаруживается при следующем запуске. Дневной лимит учитывает и попытки с откатом.
5. Файл `/tmp/zhealth-reports/latest-ИМЯ` содержит имя последнего завершённого отчёта для цели. Занятый тестер не стирает предыдущий результат и не расходует интервал.

Элементы управления на вкладке:

- **Автоподбор по расписанию** — добавляет/удаляет cron-запись healthcheck.
- **Автоприменение победителя** — `AUTOPROMOTE` в healthcheck; при выключенном флаге автотест только пишет журнал.
- **Кулдаун, часов** — минимальный интервал между автотестами одного домена (1–168, по умолчанию 6).
- **Промоутов в сутки** — защитный лимит автоприменений (0–20, по умолчанию 3).
- **Проверить сейчас** — внеочередной запуск мониторинга.

Журналы: мониторинг — `/tmp/zhealth.log`, автоподбор и промоуты — `/tmp/zhealth-autotest.log`, счётчики сбоев — `/tmp/zhealth-fails`. Журналы и результаты в `/tmp` очищаются при перезагрузке; счётчик применений и резервные копии хранятся в `/root/zapret2-tools`.

«Итого» считает уникальные домены. Если домен есть в нескольких списках, запрос выполняется один раз, а результат учитывается в каждом списке. В таблице контрольный тест без обхода закреплён сверху. Стратегии сортируются по числу успешно проверенных доменов. Зелёная ячейка означает успех всей выбранной выборки, жёлтая — больше успешных доменов, чем в контрольном прогоне. При разном покрытии сравнение с контролем ещё не вычисляется.

С 2026-11-18 проверка идёт **без остановки zapret2**: тестовые потоки помечаются desync-меткой `0x40000000` до хуков живой службы, она их пропускает и продолжает обслуживать LAN. Режим реализован флагом `--no-stop` и используется из LuCI всегда (служба должна быть запущена). Классический режим с остановкой и восстановлением службы остался в CLI по умолчанию, watchdog и кнопка восстановления актуальны для него.

## Как выполняется проверка

Профиль собирается штатным генератором Zapret Manager в частной UCI-копии. В пакетном режиме проверяется его техника на доменах выбранных списков. Исходные включения и исключения hostlist/ipset снимаются в тестовых параметрах, автоматическое обучение списков отключается. TCP/UDP, порты, L7-фильтры, payload и Lua-действия сохраняются.

Каждая попытка запускает отдельный nfqws2 и временные nftables-правила для одного адреса и диапазона исходных портов тестового curl. В журнале проверяется выполнение Lua-действия. Одного успешного запроса для отметки `PASS` стратегии недостаточно, должно быть зарегистрировано действие.

GET использует диапазон 0–65535 байт и User-Agent как у теста Zapret Manager. HEAD доступен для быстрой проверки корня домена. Контрольный прогон и профили используют один выбранный IPv4. Для точного сопоставления домена, адреса и результата HTTP-редирект записывается как ответ исходного домена. Ответы HTTP 4xx/5xx имеют отдельный неопределённый статус. Для CDN и служебных адресов корень `/` может требовать другого URL.

Превью и само видео YouTube требуют отдельного теста конкретного URL через CLI `--url`. Сводка корней доменов подтверждает доступность запросов в условиях теста. Для QUIC нужна сборка curl с HTTP3: дистрибутив включает статический musl-бинарь `curl-h3` (curl 8.23.0, HTTP3+ECH, aarch64; проверенные sha256 в changelog), который устанавливается в `/opt/zapret2/curl-h3`. Тестер и управляющий скрипт подхватывают его автоматически через симлинк `/opt/zapret2/h3bin/curl`, тогда режим QUIC доступен в меню. Игровой и голосовой UDP требуют тестов их собственных протоколов.

## Файлы и отчёты

- `/root/zapret2-tools/strategy-check-openwrt.sh` — основной тестер и CLI.
- `/root/zapret2-tools/strategy-check-control.sh` — запуск, остановка, статус, promote и cron-действия для LuCI.
- `/www/luci-static/resources/view/zapret2/strategy-compare.js` — вкладка.
- `/opt/zapret2/healthcheck.sh` — мониторинг доменов, автотриггер и автопромоут (cron).
- `/opt/zapret2/curl-h3` + `/opt/zapret2/h3bin/curl` — статический curl с HTTP3 для QUIC-режима.
- `/tmp/zapret2-strategy-ui/job-*/report/` — результаты конкретного запуска.

Сводную таблицу и подробности можно скачать кнопками TSV. Отчёты в `/tmp` хранятся до перезагрузки. Задания из меню сохраняют все числовые результаты в TSV, а подробные журналы ограничены последней ошибкой каждой стратегии. Это сокращает расход RAM на длинных прогонах. При нехватке места прогон прерывается с сохранением частичной сводки и восстановлением службы.

## Повторная установка

Архив содержит установщик и рабочие файлы: `strategy-check-openwrt.sh`, `strategy-check-control.sh`, `strategy-compare.js`, а также опциональные `healthcheck.sh` (мониторинг и автоподбор) и `curl-h3` (статический curl с HTTP3). Распакуйте его в отдельную папку, скопируйте эту папку на роутер и запустите в ней.

```sh
sh install-strategy-compare.sh --check
sh install-strategy-compare.sh
```

Установщик проверяет структуру существующего LuCI-приложения, добавляет require и вкладку в текущий `app.js`, дополняет ACL точным путём к управляющему скрипту и обновляет версию ресурсов для сброса браузерного кэша. Резервная копия находится в `/root/zapret2-tools/backups/ui-ДАТА-PID/`. Если обычная установка завершится ошибкой после начала замены, установщик восстанавливает сохранённые файлы. Дополнительно: ставит `healthcheck.sh` (с cron-записью и строкой в `/etc/sysupgrade.conf`) и `curl-h3` (из архива или скачиванием релиза stunnel/static-curl для aarch64/x86_64; при неудаче — предупреждение, QUIC просто останется скрыт).

После обновления пакета `luci-app-zapret2` точка подключения вкладки может быть перезаписана. Для такой ситуации предназначена повторная установка из архива. Неподдерживаемая структура приложения вызывает ошибку предварительной проверки.

## Откат вкладки на исходном роутере

Исходные файлы сохранены перед первой интеграцией.

```sh
cp -p /root/zapret2-tools/backups/20261112-ui/app.js /www/luci-static/resources/view/zapret2/app.js
cp -p /root/zapret2-tools/backups/20261112-ui/version.json /www/luci-static/resources/view/zapret2/version.json
cp -p /root/zapret2-tools/backups/20261112-ui/acl.json /usr/share/rpcd/acl.d/luci-app-zapret2.json
/etc/init.d/rpcd restart
```

CLI-тестер останется доступен по постоянному пути.

## Изменения от 2026-11-18 (для авторов исходной версии)

Сводка всех доработок второго этапа. Версия ресурсов LuCI: `strategy-compare.6`.

### Поведение
- **Прогоны без остановки службы** (`--no-stop`, теперь всегда из LuCI): тестовые потоки
  (исходные порты 61000–61099) помечаются desync-меткой `0x40000000` в цепочках
  `premarkout` (postrouting prio 98, до хука zapret2 на 99) и `premarkin` (prerouting prio -103,
  до -99), поэтому живой nfqws2 их пропускает. Изолированность теста сохраняется, LAN не страдает.
  `setup_firewall` стал идемпотентным; контрольный прогон в no-stop тоже маркируется и остаётся
  контролем без тестовой стратегии. NetShift может обработать этот запрос по своим правилам.
  Классический режим с остановкой службы — в CLI без `--no-stop`.
- **Throughput-проба**: флаги `--throughput N --throughput-url URL --min-speed KBps --tp-maxtime S`.
  После `HTTP_OK` запрашивается диапазон в N МиБ (первая попытка). Начиная с версии 7
  для оценки скорости нужны успешный curl, HTTP 200 или 206 и ровно N МиБ. При другом
  коде ответа или размере тест возвращает `TP_FAIL`. Скорость сравнивается с порогом:
  `TP_OK / TP_SLOW / TP_FAIL`. Отдельный хост резолвится mdig и добавляется в тестовый
  файрвол (наборы DESTS/DPORTS), поэтому замер идёт через проверяемую стратегию.
- **Promote**: `strategy-check-control.sh promote NAME` и кнопка «Применить» в строке
  стратегии. Резервная копия `/etc/config/zapret2`, `uci enabled=1`, перезапуск, статус;
  отказ при идущей проверке.
- **Автотриггер и автопромоут** в `healthcheck.sh`: 2 сбоя домена подряд → sanity-проверка
  ya.ru/mail.ru/vk.com → автотест включённых стратегий → автоприменение победителя
  (кулдаун 6 ч/домен, лимит 3 в сутки, бэкап, поверка). Параметры — переменные в шапке скрипта.
- **Управление cron из LuCI**: действия `cronstatus` / `cronset` / `cronrun` в управляющем
  скрипте и секция «Автоподбор стратегий (cron)» на вкладке.

### QUIC / HTTP3
- В дистрибутив добавлен статический musl-бинарь `curl-h3` (curl 8.23.0, HTTP3+ECH, aarch64):
  sha256 архива релиза `e20f26e5…6199`, бинаря `3a7c6818…d6fc` (stunnel/static-curl, релиз 8.23.0-1).
- Тестер и управляющий скрипт подхватывают его через `/opt/zapret2/h3bin/curl` (PATH-префикс),
  поэтому пункт quic в меню появляется автоматически. Раньше проверка шла по системному curl
  без HTTP3 и пункт был скрыт — это исправлено.

### Установщик
- Ставит `healthcheck.sh` (бэкап старого, cron-запись `# zhealth`, строка в `/etc/sysupgrade.conf`).
- Ставит `curl-h3` из архива или скачивает релиз для aarch64/x86_64; создаёт симлинк и запись
  в sysupgrade.conf; отсутствие бинаря — предупреждение, а не ошибка.
- Версия ресурсов поднимается до `.strategy-compare.6`.

### Замечания по эксплуатации
- QUIC-тест требует стратегий с `protocol udp`; TCP-стратегии в нём корректно `SKIP_PROTOCOL`.
- Throughput на корнях доменов малоинформативен (~1 МБ ответ) — используйте `--throughput-url`
  на медиа-эндпоинт (например, сегмент googlevideo или speedtest).
- Все журналы мониторинга в `/tmp` и переживают только перезагрузку.

## Маршрут и время проверки (версия 7)

В LuCI нажмите ячейку сводной таблицы. В деталях и TSV поле route показывает NetShift при наблюдаемом перехвате запроса или dev/ИМЯ при наблюдаемом выходе пакетов через интерфейс роутера. Значение unknown означает, что маршрут подтвердить не удалось. Для отдельной загрузки маршрут измеряется отдельно. Поле описывает участок на роутере, а не выходной сервер подписки. Старые отчёты могут не содержать этой колонки.

Проверка начинает запрос после регистрации очереди nfqws2 в ядре. На системах без ucode или списка очередей используется прежняя пауза.

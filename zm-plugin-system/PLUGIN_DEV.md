# Как написать свой плагин для Zapret Manager (SPA :7788)

Плагин = **manifest.json** (описание интерфейса) + **backend.sh** (логика).
JavaScript писать не нужно: страницу строит универсальный рендерер.

## Структура плагина

```
my-tool/
├── manifest.json    # что показать: виджеты, действия
└── backend.sh       # что выполнить: действия → JSON в stdout
```

## manifest.json

```json
{
	"id": "my-tool",
	"title": "Мой инструмент",
	"version": "1.0",
	"sub": "Короткое описание для меню",
	"icon": "layers",
	"group": "Плагины",
	"description": "Текст под заголовком страницы.",
	"widgets": [
		{ "type": "status", "title": "Статус", "action": "status" },
		{ "type": "table",  "title": "Данные", "action": "stats",
		  "columns": ["Колонка 1", "Колонка 2"], "refresh": 30 },
		{ "type": "button", "label": "Запустить", "action": "start",
		  "desc": "Пояснение", "output": true },
		{ "type": "form",   "title": "Добавить узел", "label": "Добавить",
		  "action": "add",
		  "fields": [ { "name": "host", "label": "Адрес",
		                "placeholder": "example.com", "required": true } ] },
		{ "type": "log",    "title": "Журнал", "action": "log", "refresh": 15 }
	]
}
```

Поля верхнего уровня:

| Поле | Обязательное | Назначение |
|---|---|---|
| `id` | да | `a-z`, `0-9`, `-`. Имя каталога и маршрута |
| `title` | да | Заголовок в меню и на странице |
| `sub` | нет | Подпись в меню |
| `icon` | нет | Иконка меню (по умолчанию `layers`; есть ещё `activity`, `shield`, `globe`, `cpu`…) |
| `group` | нет | Группа меню (по умолчанию «Плагины») |
| `version`, `description` | нет | Отображаются на странице |
| `widgets` | да | Массив виджетов сверху вниз |

## Типы виджетов (v1.1)

| type | Что рисует | Ответ backend на `action` |
|---|---|---|
| `status` | Таблицу «ключ: значение» | `{"ok":true,"data":{"Ключ":"Значение"}}` |
| `table` | Таблицу с колонками из `columns` | `{"ok":true,"rows":[["a","b"],["c","d"]]}` |
| `button` | Кнопку; `output:true` покажет `log` под кнопкой | `{"ok":true,"message":"Готово","log":"детали"}` |
| `form` | Поля ввода + кнопку; значения уходят аргументами | `{"ok":true,"message":"Готово","log":"детали"}` |
| `log` | Текстовый блок (журнал) | `{"ok":true,"log":"многострочный текст"}` |

Дополнительные поля виджетов: `title`, `desc` (у button/form), `refresh`
(секунды автообновления, 0/нет — только при открытии страницы и после
действий), `danger` (красная кнопка), `output` (показать log после нажатия;
у form по умолчанию включён, `output:false` отключает).

Поля формы (`fields`): `name`, `label`, `placeholder`, `required`
(без заполнения кнопка не сработает), `password` (маскирует ввод).
Значения передаются в backend как `$2`, `$3`, … в порядке полей.

**Обновление данных:** после успешного `button`/`form` все остальные виджеты
страницы перезапрашиваются сразу — ждать таймер `refresh` не нужно.

Ошибка любого действия: `{"ok":false,"error":"текст"}` — покажется в интерфейсе.

## backend.sh

```sh
#!/bin/ash
case "${1:-}" in
	status) printf '{"ok":true,"data":{"Состояние":"работает"}}' ;;
	stats)  printf '{"ok":true,"rows":[["1.1.1.1","245"],["8.8.8.8","116"]]}' ;;
	start)  /etc/init.d/mytool start >/dev/null 2>&1 \
		&& printf '{"ok":true,"message":"Запущено"}' \
		|| printf '{"ok":false,"error":"не удалось запустить"}' ;;
	add)    host="$2"   # ← значение поля формы
		[ -n "$host" ] && printf '{"ok":true,"message":"Добавлен %s"}' "$host" \
		|| printf '{"ok":false,"error":"пустой адрес"}' ;;
	log)    log="$(tail -n 20 /tmp/mytool.log | sed 's/\\/\\\\/g; s/"/\\"/g' | sed ':a; N; $!ba; s/\n/\\n/g')"
		printf '{"ok":true,"log":"%s"}' "$log" ;;
	*) printf '{"ok":false,"error":"неизвестное действие"}' ;;
esac
```

Правила:

- Один файл, действие — первый аргумент (`$1`), значения полей формы —
  `$2`, `$3`, …; ответ — **только JSON** в stdout.
- Backend исполняется от root через rpcd file-exec — пишите аккуратно,
  никаких `eval`; аргументы форм подставляйте только через `"$2"` в кавычках
  и валидируйте (это пользовательский ввод).
- Экранирование строк для JSON: пример в `log` выше (слэши, кавычки, переносы).
- Долго работающие действия (>2 мин) запускайте в фоне (`setsid … &`)
  и отдавайте статус отдельным действием.

## Установка и удаление

Из панели: страница **Плагины → Менеджер плагинов** (список, установка
из каталога на роутере, удаление, пересборка реестра).

Из shell:

```sh
zm-pluginctl install /path/to/my-tool   # установка/обновление
zm-pluginctl list                       # что стоит
zm-pluginctl remove my-tool             # удаление
zm-pluginctl reindex                    # пересобрать реестр вручную
```

После установки страница появляется в меню панели :7788 автоматически
(при следующем обновлении страницы браузера). Установленные плагины лежат
в `/etc/zm-plugins/<id>/`, реестр — `/www/zm-plugins/index.json`.

## Готовые примеры

- `examples/service-probe/` — таблица проб сервисов, кнопка, сводка, журнал.
- `examples/plugin-manager/` — менеджер плагинов: список, формы
  установки/удаления, кнопка реестра. Показывает работу виджета `form`.

Копируйте любой как основу:

```sh
cp -r examples/service-probe my-tool
# правьте manifest.json и backend.sh
zm-pluginctl install my-tool
```

## Ограничения v1.1

- Плагины видны только в SPA-панели :7788 (в LuCI-меню не добавляются).
- Форма — только текстовые поля (нет выбора из списка, чекбоксов, загрузки файлов).
- Страница плагина не проверяет прав доступа по отдельности: доступ к панели
  = доступ ко всем плагинам.

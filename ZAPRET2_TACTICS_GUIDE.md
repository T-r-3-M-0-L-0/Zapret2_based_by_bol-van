# Zapret2: как работать и строить тактики

Практический гайд по механике zapret2 (bol-van), построению тактик, фейковым
пейлодам и источникам адресов для листов. База — наш сетап: Windows (winws2)
и OpenWrt (zapret2 через Zapret-Manager).

---

## 1. Как zapret2 вообще работает

zapret2 **не прокси и не VPN**. Трафик идёт напрямую к серверу, а движок
(winws2 / nfqws2) перехватывает пакеты и искажает их так, чтобы ТСПУ
(DPI-оборудование провайдера) «сломалось», а конечный сервер при этом пакеты
нормально собрал.

Конвейер:

```
твой браузер → ядро → [перехват: WinDivert (winws2) / NFQUEUE (nfqws2)]
             → модификация пакетов по тактикам → провайдер (DPI) → сервер
```

- **Профиль** — набор фильтров (по L7-протоколу, порту, хостлисту, ipset'у)
  и привязанных к ним тактик. Срабатывает первый подходящий профиль.
- **Тактика** — конкретное действие над пакетом/соединением: `fake`,
  `multisplit`, `multidisorder`, `syndata`, `tamper` и т.д.
- **Lua-скрипты** — логика выбора и аргументов тактик (наши `argus`,
  `hybrid`, `steer` в `lua/`).

Фильтры профиля (что перехватывать):

| Фильтр | Смысл |
|---|---|
| `--filter-l7=http\|tls\|quic\|wireguard\|stun` | Протокол прикладного уровня |
| `--filter-tcp=80,443` / `--filter-udp=443` | Порты |
| `--hostlist=<file>` | Домены из текстового списка |
| `--hostlist-exclude=<file>` | Исключения из списка |
| `--ipset=<file>` | IP/CIDR из списка |
| `--ipset-exclude=<file>` | Исключения IP |
| `!` префикс в хостлисте (с v1.0.7) | Локальное исключение домена |

Важно: чем **точнее фильтр**, тем меньше побочек (игры, банки, CDN не должны
попадать под десинк — наш кейс с Fortnite/For Honor: игровой UDP вывели из
перехвата).

## 2. Система zapret2 подробно

### 2.1 Топ-15 команд

Windows (winws2, из каталога C:Zapret2):

| # | Команда | Зачем |
|---|---|---|
| 1 | `service.ps1` | Главное меню: служба winws2, tg-ws-proxy, ztool, автозапуск |
| 2 | `sc.exe query winws2` | Статус службы движка |
| 3 | `sc.exe stop winws2` / `sc.exe start winws2` | Ручной стоп/старт службы |
| 4 | `tasklist /FI "IMAGENAME eq winws2.exe"` | Жив ли процесс движка |
| 5 | `netsh interface tcp set global timestamps=enabled` | Обязательно для fooling=ts (Win11!) |
| 6 | `python ztool.py debug <bat>` | Живая сессия: какие профили срабатывают |
| 7 | `python ztool.py config <bat>` | bat-стратегия -> @config-файл winws2 |
| 8 | `python ztool.py watch --once` | Пробы ключевых доменов (DPI-окно) |
| 9 | `python ztool.py wfcheck <bat>` | WinDivert-фильтры: поиск CPU-ловушек |
| 10 | `python ztool.py hostlists stats` | Гигиена списков (дубли, мусор) |
| 11 | `python ztool.py diag` | Диагностический бандл logs\diag_*.zip |

| 14 | `type logs\winws2.log` (или Get-Content -Tail 50) | Журнал движка |
| 15 | `blockcheck2` | Автоподбор рабочей тактики по домену |

### 2.3 Основные конфиги

- **bat-стратегия (Windows)** — набор вызовов winws2 с профилями:
  фильтры (`--filter-l7`, `--filter-tcp/udp`, `--hostlist`, `--ipset`) +
  действие (`--dpi-desync=...`) + lua (`--lua-init=@file.lua`).
  Один вызов = один независимый экземпляр логики; порядок профилей важен —
  срабатывает первый совпавший.
- **UCI /etc/config/zapret2 (роутер)** — те же профили секциями
  `config profile`: option filter_*, option desync, list hostlist и т.д.
  Правка -> `uci commit zapret2` -> `service zapret2 restart`.
- **Списки**: hostlist — домен на строку, `#` комментарий, `!` исключение
  (v1.0.7+); ipset — IP/CIDR на строку.
- **Lua**: `argus` (гибридные решения по ответу DPI), `hybrid` (наша
  рабочая логика), `steer` (маршрутизация профилей). Точка входа —
  `--lua-init=@<file>`, дальше require своих либ из `lua/`.

### 2.4 Правила целостности конфига (v1.0.7+)

- Один и тот же файл листа одного типа нельзя указывать дважды в профиле —
  раньше проглатывалось, теперь конфиг отваливается.
- Текстовый фильтр WinDivert ограничен 16K (winws2) — при раздувании
  хостлистов следить через `ztool wfcheck`.
- `--wf-priority` (winws2): blockcheck2 гонять с `--wf-priority=2000`,
  чтобы не конфликтовать с рабочим движком.

## 3. Основные тактики и когда их применять

### 3.1 fake — подсадка фейкового пакета
Движок отправляет «мусорный» пакет с признаками начала сессии до/вместо
настоящего. DPI запоминает фейк как начало потока и дальше смотрит «не туда».

Ключевые параметры:
- `--dpi-desync-fooling=md5sig,badseq,ts` — как испортить фейк, чтобы сервер
  его отбросил, а DPI съел: битый md5sig (TCP-опция), невалидный SEQ,
  timestamps. **Внимание:** `ts` требует включённых TCP timestamps в Windows
  (`netsh interface tcp set global timestamps=enabled`) — наш кейс.
- `--dpi-desync-fake-tls=<blob>` / `--dpi-desync-fake-quic=<blob>` — чем
  кормить DPI (см. раздел 4).
- `--dpi-desync-repeats=N` — сколько раз повторить фейк.
- `--dpi-desync-fake-sni=domain` — подменный SNI в фейковом ClientHello.

### 3.2 multisplit / multidisorder — разрезание
Первый пакет (TLS ClientHello, HTTP-запрос) режется на куски; DPI либо не
собирает их обратно, либо теряет границы SNI.
- `multisplit` — куски идут по порядку.
- `multidisorder` — куски идут с нарушением порядка (сервер соберёт, DPI — нет).
- Точки разреза: `--dpi-desync-split-pos=1` (после первого байта), `midsld`
  (середина домена второго уровня), `sld+1`, `host+2` и т.д.

### 3.3 syndata — данные внутри SYN
Отправка данных прямо в SYN-пакете (TCP Fast Open стиль). DPI часто не ждёт
данных в SYN и пропускает их. Тяжёлая тактика, работает не везде.

### 3.4 udp2icmp / udp2raw (zapret-obfs)
UDP маскируется под ICMP — обходит провайдерский CGNAT/подавление UDP
(появилось в v1.0.7, используем для Youtube UDP/QUIC).

### 3.5 tamper
Мелкие искажения: изменение TTL, порядка опций TCP, fragmentation IP.

### Порядок перебора при построении новой тактики
1. **fake + badseq/md5sig** — самый дешёвый по накладным, стартовать с него.
2. **multisplit** с разными `split-pos` (1 → midsld → комбинации).
3. **multidisorder** — если split проходит, но режется скорость/стабильность.
4. **syndata** — когда DPI научился собирать split.
5. Комбинации: fake + multisplit одновременно (наша гибридная тактика).

Проверка каждого шага — `blockcheck2` (см. раздел 6), не «на глаз».

## 4. Фейковые пейлоды: что это и откуда брать

Фейк — это бинарный блоб, который подсовывается DPI. Встроенные в движок
(доступны по имени в `--dpi-desync-fake-*`):

| Имя | Что изображает | Когда использовать |
|---|---|---|
| `tls_default` | Стандартный TLS ClientHello | Базовый вариант для TLS |
| `quic_initial` | Начальный QUIC-пакет | UDP/443, HTTP/3 |
| `quic_v2` | QUIC v2 | Если quic_initial детектится |
| `http_get` | Обычный HTTP GET | Порт 80 |
| `stun` | STUN-запрос | UDP-сервисы |
| `wireguard` | WG handshake | UDP-туннели |
| `dht` | BitTorrent DHT | Маскировка под p2p |
| `0x00...` / файл | Свой блоб (hex или path) | Кастомные случаи |

Правила выбора фейка:
- Фейк должен **соответствовать протоколу** фильтра: TLS-фейк для TLS,
  QUIC-фейк для QUIC — DPI сверяет сигнатуры.
- Размер имеет значение: слишком короткий фейк не «защёлкнет» сессию DPI.
- Ротация: если провайдер начал детектить конкретный фейк, меняется только
  параметр фейка, а не вся тактика — поэтому у нас вынесено в профили.

Свои пейлоды: файлом в `files/fake/` (в zapret2-дереве) и ссылка по имени.
Достать образец настоящего ClientHello можно Wireshark-дампом с чистого
подключения к крупному CDN.

## 5. Откуда брать DNS/IP для листов

Два типа списков: **hostlist** (домены) и **ipset** (IP/CIDR).

### Домены (hostlist)
- Ведение вручную: добавляем то, что реально используем (наши списки:
  youtube, discord, meta, cdn-балансировщики filmix/alloha/showy).
- Субдомены не нужны, если включён автоподхват поддоменов — достаточно
  `example.com` (но googlevideo.com и ytimg.com — разные зоны, обе нужны).
- Просмотр реальных доменов сервиса: вкладка Network в DevTools браузера
  (chrome://net-export → анализ, как мы делали для googlevideo/аватаров
  Discord — cdn.discordapp.com, media.discordapp.net).

### IP (ipset)
Для сервисов, где SNI-подход не работает (жёсткий DPI по IP, QUIC к
динамическим CDN):

1. **Резолв через DoH** (обходя провайдерский DNS):
   ```sh
   curl -s "https://1.1.1.1/dns-query?name=example.com&type=A" -H "accept: application/dns-json"
   ```
2. **Готовые CIDR-списки ASN** (стабильнее точечных IP):
   - `whois -h whois.radb.net -- '-i origin AS15169'` (Google) и т.п.
   - ipdeny.com / статистика RIPE для диапазонов стран/провайдеров.
3. **Готовые сообщества**: antizapret-листы, community-списки для
   youtube/discord — брать как основу и резать под себя.
4. **Самосбор**: `blockcheck2` сам резолвит и предлагает ipset по итогам проверки.

### DNS для самих листов: откуда брать «правильные» ответы
- Провайдерский DNS в РФ подменяет ответы — для построения ipset использовать
  только **DoH/DoT**: Cloudflare (1.1.1.1), Google (8.8.8.8), dns.google,
  или DoH-резолв внутри самого роутера (наш https-dns-proxy кейс: если DoH
  лёг — проверять доступность аплинка, см. журнал).
- Проверка, что DNS подменён: `nslookup domain <провайдерский>` vs
  DoH-запрос — расхождение = подмена, и именно эти IP надо брать из DoH.

## 6. Инструменты выработки тактики

| Инструмент | Что даёт |
|---|---|
| `blockcheck2` | Автоперебор тактик против конкретного домена, выдаёт рабочую комбинацию. Запускать с `--wf-priority=2000` (v1.0.7+). **На Windows включить TCP timestamps.** |
| `ztool debug <bat>` (Windows) | Живая сессия: какие профили срабатывают по реальному трафику |
| `ztool wfcheck <bat>` | Проверка WinDivert-фильтров на CPU-ловушки |
| strategy-check (OpenWrt) | Прогон стратегий по списку целей + автоподбор по cron |
| chrome://net-export | Какие домены/IP реально дёргает сервис |

Методика: blockcheck2 по проблемному домену → рабочая комбинация → оформить
профилем с узким фильтром → добавить в strategy-check для регрессии →
наблюдение неделю → закрепить.

## 7. Антипаттерны (наши шишки)

- **Перехват всего трафика** — ломает игры/банки/странные CDN. Только узкие фильтры.
- **Игровой UDP в десинке** — Fortnite «initial connection failed», чёрный
  экран наблюдателя. Игровые порты/подсети — в exclude.
- **`--dpi-desync-fooling=ts` при выключенных TCP timestamps** — Windows 11
  по умолчанию выключает; включать `netsh interface tcp set global timestamps=enabled`.
- **Дубли листов одного типа в профиле** — с v1.0.7 запрещено, конфиг отвалится.
- **Один профиль на всё** — youtube QUIC и meta лучше держать раздельными
  (наш Youtube_UDP-профиль), чтобы крутить их независимо.
